# 私记 · 本地私人手记 PWA

移动端优先的本地私人照片手记。界面是一册暖纸、墨色与朱砂印章的「纸本手记」：一天可以记很多笔、每笔多张照片，另有独立的佩戴时段、日历/照片时间线、回顾统计和完整加密备份。**没有账号、后端、照片上传、广告、遥测或远程字体。** 第一次联网缓存程序后可离线使用。

## 界面与设计

- **纸本手记**：暖纸底色（`#f4efe6`）、墨色文字、朱砂印章（`#a83a28`）与苔绿点缀；宋体大标题 + 系统无衬线正文；细线分隔、小圆角纸页、相片纸边和印章标记，全部由 CSS 与系统字体绘制，不加载任何网络字体或装饰图片。
- **日读 / 夜读**：浅色为「日读」，深色为「夜读」（墨纸 + 米色文字、朱砂提亮）；可在设置里跟随系统或手动切换，浏览器工具栏颜色同步。
- **文案**：安静、亲密、克制，第二人称短句；底部导航为 **今天 / 日历 / 记录 / 回顾 / 设置**；不使用装饰性页面大标题（每页只保留读屏可读的功能名），空状态、按钮和提示统一重写，功能术语（佩戴、清洁小憩、时段、装备、命运轮盘）保持可理解。
- **设计依据**：`design/REDESIGN-BRIEF.md`（概念、色板、字体、排版与组件规范）、`design/COPY.md`（全部界面文案终稿）。逐页截图可用 `node scripts/screenshots.mjs` 重新生成（390×844 与 1280×900、日读/夜读双色，输出到 `design/screenshots/after/`）。
- 可访问性保持：44px 触控目标、可见焦点环、`prefers-reduced-motion`、文字对比度与安全区适配。

## 安装到 iPhone

1. 将项目部署到 HTTPS 静态网站（下面提供 GitHub Pages 配置）。不要直接用“文件”App 打开 `index.html`。
2. 使用 Safari 打开部署地址，分享 → 添加到主屏幕。
3. **从主屏幕启动后再建立本地空间**，设置至少 8 字符的解锁密码。
4. 设置页显示「应用已缓存，可以离线使用」后，再启用飞行模式测试。
5. 点底部「记录」 → 拍一张/从相册选 → 收进今天。其它信息都是可选项。每次记录可以选择多张照片；一次系统相机拍摄后可再次点「拍一张」追加。

应用不会设置佩戴目标，也不会因为拍照而自动创建佩戴时段。设备锁屏、后台计时不会依赖页面定时器；再次打开后按照时间戳计算。

## GitHub Pages 部署（lockweb）

仓库：`hu-border-collie/lockweb`。程序静态资源的计划地址为 `https://hu-border-collie.github.io/lockweb/`；**只有部署成功后此地址才可用**。

1. 仓库 **Settings → Pages → Build and deployment → Source → GitHub Actions**。
2. 提交后 `Validate PWA` 工作流运行单元测试、构建、Chromium 与 WebKit 移动视口端到端测试。
3. 测试通过后 `Deploy GitHub Pages` 自动构建 `/lockweb/` 路径并发布。也可以在 Actions 手动运行部署工作流。
4. 确认 Pages 和 Actions 都显示成功后，在 Safari 打开实际部署地址。

首次发布若提示 `Get Pages site failed`，表示仓库尚未启用 Pages。先完成第 1 步，再在 Actions → Deploy GitHub Pages → Run workflow 启动发布。默认工作流令牌不能自动初始化 Pages，项目不会请求或保存你的访问令牌。

**仓库可以保持私有，但 GitHub Pages 的私有仓库功能需要相应套餐（如 GitHub Pro）；GitHub Free 通常要求公开仓库。** 本项目不自动改变仓库可见性。代码公开并不公开设备数据库；网站资源公开也不共享任何人的本地照片。GitHub Pages 官方说明：<https://docs.github.com/en/pages/getting-started-with-github-pages>。

如果套餐不支持或不想公开源码，可将 `dist/` 部署到支持 HTTPS 的其它静态托管，例如 Cloudflare Pages（构建命令 `npm run build`、输出 `dist`，移除 `/lockweb/` 环境变量）。静态站点首次载入和检查更新会访问托管服务，但个人记录与照片不会发送到该服务。

## 五个页面

- **今天**：当前佩戴状态、实时持续时间、开始/结束佩戴、清洁小憩、独立时段、今日记录和最近照片；底部中间是醒目的「记录」印章按钮，另有命运轮盘入口。
- **日历**：月历每日笔数、当天全部记录、按日期分组的照片时间线；时间线每批加载 20 笔。照片支持全屏、上一张/下一张、双击/双指缩放及拖动，并可跨记录选择两张照片对比。
- **记录**：相机/相册、多照片、自动保留秒级时间戳、手动时间、备注、标签、佩戴状态、舒适度、装备与时段关联、照片打码；编辑时可拿掉已有照片或追加照片。删除一页会删除关联照片。
- **回顾**：今日/本周（周一开始）/本月笔数、照片总数、佩戴总时长、最长的一次佩戴、连续记录天数、12 周足迹热力图、7/30/90 天趋势、舒适度与标签/装备/时段的交叉统计、匿名小结与命运历史。
- **设置**：现在合上、更换密码、导出加密备份、用备份恢复、长期保留申请、本机存储占用、日读/夜读外观、装到主屏幕与离线说明、清空手记，以及模板/快捷标签/装备档案、快速解锁入口。

  styles/                 纸本手记样式模块：tokens / shell / home / calendar /

| 实体        | 解密后字段                                                                  | IndexedDB 中实际保存           |
| ----------- | --------------------------------------------------------------------------- | ------------------------------ |
| Entry       | id、timestamp、note、tags、wearing、comfort、photoIds、createdAt、updatedAt | id + AES-GCM 加密 JSON         |
| WearSession | id、start、end/null、note                                                   | id + AES-GCM 加密 JSON         |
| Photo       | id、关联记录、JPEG 图片、JPEG 缩略图                                        | id、ownerId + 两个加密二进制包 |
| VaultConfig | 随机库 id、盐、派生参数、被包装的随机数据密钥                               | 无密码；只有盐、参数和加密密钥 |
| Revision    | 数据修订号                                                                  | 用于拒绝其它窗口产生的过期写入 |

照片引用的随机 id/ownerId 和条目数量不加密；所有照片像素、缩略图、记录时间、备注、标签、舒适度、状态与时段内容加密。启用快速解锁时，站点、凭据 id、公钥、配置指纹、随机派生输入及窗口时限提示作为本地元数据保存；数据密钥包装与授权时间的认证副本保持加密，明文提示不作为解锁依据。主题偏好是唯一写入 localStorage 的内容。解锁数据只留在当前页面内存中。

当前数据库版本为 5：版本 1 升级增加修订号，版本 2 / 3 / 4 升级保留修订号与全部密文。v5 在一次升级事务内，将元数据、打卡、时段和照片分别迁移到独立命名的新表；逐行复制照片，不一次加载全部图片，也不改变密码或快速解锁绑定。任何复制失败都会回滚，保留旧表与全部数据。Dexie 会在版本不匹配时重试打开，因此不能仅依赖版本号隔离旧客户端。旧版重建的旧表与新版表完全分离，其编辑、改密、清空或恢复不会改变新版保险库；旧界面可能显示空库，应更新页面后使用。升级时遇到其它窗口会关闭旧连接，需要更新并重新打开旧窗口。未来数据库版本必须添加显式迁移，不能通过删除数据库升级。

## 本批功能扩展

- **防窥（#1）**：每次解锁默认开启，可在顶部眼睛按钮切换。所有缩略图模糊，按住约 350 ms 临时预览，松开、移开、取消手势或切后台立即恢复。键盘空格按住可预览；普通点击仍打开大图。防窥只遮挡列表照片，不隐藏备注，也不替代锁定。
- **照片打码（#2）**：记录草稿中的新照片和已有照片均可使用黑色笔刷或马赛克，支持笔刷粗细、撤销、重置。应用打码后仍须保存这一页；保存成功时以事务替换大图与缩略图。取消编辑保留原记录。马赛克仅降低细节，需要彻底遮挡时使用黑笔。
- **系统快速解锁（#3）**：主密码确认后创建通行密钥，再验证 PRF 派生与密钥包装成功后启用。锁定界面提供「用面容 / 指纹打开」按钮。新绑定默认永久有效，每次解锁仍须系统验证；也可选择 1 天 / 7 天 / 30 天，从最后一次主密码验证计时，正确输入主密码会续期，快速解锁本身不续期。已有绑定保留原有期限，可在设置 → 快速解锁 →「重新验证或调整有效期」选择「永久有效」，确认主密码并完成系统验证后复用原通行密钥。不支持、取消或失败时保持密码入口。
- **清洁小憩（#4）**：今天页可暂停和恢复进行中的时段，也可在时段编辑页补记或修改小憩。实际时长先在每个时段内扣除小憩，再合并重叠区间。最长连续佩戴按设置中的小憩上限计算：短小憩保留连续周期，长小憩截断；任何小憩都不计入实际时长。
- **照片对比（#5）**：日历和时间线可跨记录选择两张照片，支持并排、卷帘滑块、同步缩放及拖动，显示拍照时间的间隔。退出或锁定释放两张大图的临时 URL。
- **模板与标签（#6）**：设置中维护多个记录模板及快捷标签。套用模板会填充备注，已有备注需确认替换；标签可点击选择或取消。
- **装备档案（#7）**：支持名称、材质、规格、购买/启用日期和备注，可关联时段与打卡。归档后停止用于新选择，但保留历史关联与统计。打卡与时段的装备选择各自明确保存。
- **匿名小结（#8）**：回顾页本地生成图片，先预览再保存或系统分享。输出只允许连续天数、累计整小时数及里程碑；热力图剪影须单独勾选，因为仍会透露每日分布。不包含照片、备注、标签、装备或精确时间。
- **交叉统计（#9）**：展示实际佩戴小时分组的平均舒适度与样本数、标签评分、记录小时与状态分布、装备时长及评分。未评分显示未知，不作为零。时长评分只使用显式关联时段且处于实际佩戴中的打卡，不猜测旧记录的归属；可编辑旧记录补充关联。图表表示记录相关性，不构成身体适应度结论。
- **存储分析（#10 的只读部分）**：按记录月份显示照片数量和加密图片字节数，不含索引与程序缓存。分析按需执行；数据变化后重新分析。尚不提供压缩或删除大图。
- **命运轮盘（#11）**：今天页进入加权轮盘；每日仪式或自由模式，支持预设、自定义扇区、一次性写进今日记录备注和关联当前时段。回顾页提供分类计数与分页历史。

上述配置、装备、记录关联和轮盘历史均纳入加密备份；快速解锁绑定不进入备份，需要在新设备上重新启用。#10 的有损归档尚未实现。

## 命运轮盘

1. 今天页 → **命运轮盘**。默认“温和日常”与每日仪式：今天新建且拍照时间也在今天的记录点亮轮盘，每个设备本地日期最多抽取一次。补记过去日期或只修改旧记录的时间不点亮今日仪式。
2. 右上角“调整轮盘”入口可切换自由模式、载入“温和日常”或“硬核加时”预设，编辑轮盘名称与 2–24 个扇区。每个扇区有名称、类型、整数权重和配色；加时类型另有分钟数。概率和可视面积均按权重分配，完整名称及概率显示在图例中。
3. 结果使用 `crypto.getRandomValues()` 加拒绝采样生成，避免直接取模的偏差。抽中结果、时间、当天日期、时区偏移、扇区内容和权重先加密保存，事务成功后才播放减速动画；动画期间关闭弹层、刷新或锁定，重新打开仍可查看已保存结果。支持减少动态效果设置。震动仅在浏览器提供 `navigator.vibrate` 时尝试，不支持时静默跳过。
4. 切换模式、换预设、编辑配置或删除今日记录均不重置每日仪式次数。自由模式可多次抽取，每次都保留历史；修改配置不会改写旧结果。
5. 最近的今日判定可选择一条今日记录，点击“写进今天的记录”。原备注与照片保留，备注和“已写入”标记同事务提交，同一判定不能重复追加。历史目标记录删除后保留判定自身的历史标记。
6. 抽取时存在进行中的佩戴时段，就记录其关联；今天页展示该时段最近一次加时或奖励判定。**判定仅作记录，不自动延长佩戴、结束时段或启动小憩；实际计时不受轮盘影响。** 可按自己的决定操作原有时段按钮。
7. 回顾 → **命运历史**显示总次数、仪式/自由次数、类型分布与每次判定的原始概率，每批展示 20 条。配置和最多 20,000 次历史作为一个 AES-GCM 包保存在现有加密元数据表，照片数据库无需迁移；清空手记会同时清除轮盘配置和历史。

每日次数是本地使用规则，不承诺抵御主动修改设备日期/时区、清空数据库或回放旧备份。新备份会保留原始日期与次数；没有账号或后端校时服务。

## 时间统计规则

- 打卡与佩戴时段是独立实体。一日允许任意多次打卡，一个时段可有多次打卡。
- 进行中的时段以“现在”为结束时间。只允许一个进行中的时段。
- 累计/每日佩戴时间先取全部时段的并集，重叠部分和相邻时段只计算一次。
- 有小憩的时段先扣除自身小憩；另一时段覆盖这段时间时，仍按并集计算实际佩戴。进行中的小憩不计时，结束佩戴会同时关闭它。
- 每日时长按设备本地午夜切分，支持跨天和夏令时日，不假定每日恒为 24 小时。
- 最长连续佩戴按每个原始时段及小憩阈值计算，不把两次相邻佩戴合成单次，不包含小憩时长。
- 当前连续天数允许今天尚未打卡时延续到昨天；相同日期多次打卡只计一天。早于昨天中断则归零。
- 手动时间不允许在未来，结束时间必须晚于开始时间。旅行或修改设备时区会改变“本地日期”的归属；存储的绝对时间戳不改变。

## 照片与 iPhone 格式

- 尝试浏览器原生解码，包括 Safari 支持的 HEIC；不支持时使用编译在程序内的 `heic-to/csp` 本地转换，不联网。
- 不能转换的特殊 HEIC 会显示明确错误，可改用相册导出的 JPEG，或相机设置 → 格式 → 兼容性最佳。
- 在 canvas 中按浏览器解码后的方向转成 JPEG，最长边 2560 px、质量 0.88；缩略图最长边 360 px、质量 0.72。
- **保存的是处理后的图片，不保留相机原始文件、Live Photo 或 EXIF。** 备份完整保留应用实际存储的 JPEG 和缩略图。
- 每张源文件上限 40 MB、100 MP，图片逐张处理，避免批量解码同时耗尽内存。缩略图只在接近可见区域时解密，页面退出/锁定后释放 object URL。
- 浏览器可返回配额不足；保存/恢复以事务进行，失败会显示错误并回滚，打卡草稿在页面仍打开时保留。系统终止进程可能丢失尚未保存的草稿。

## 密码、加密与锁定

- PBKDF2-HMAC-SHA-256、随机 128 位盐、600,000 轮派生密码密钥。
- 随机 256 位数据密钥用 AES-256-GCM 包装；每条记录、原图、缩略图用独立随机 96 位 IV 和区分对象 id 的附加认证数据加密。
- 修改密码只重新包装同一数据密钥，无需重写全部照片。
- 关闭页面/手动锁定后需重新输入密码；普通切后台超过 1 分钟，返回时锁定。后台立即显示中性遮罩。系统拍照、选图、选备份、保存备份可能暂时隐藏 Safari，因此这些系统操作有最多 15 分钟的豁免，避免操作途中丢失状态。
- 密码不上传、不保存明文、不提供找回。弱密码可能被离线猜测；请使用足够长的独立密码。解锁时数据会出现在页面内存，应用不承诺抵御已被控制的设备或恶意浏览器扩展。
- 忘记解锁密码时只能删除本机保险库重新开始，然后凭备份密码恢复。重置有明确文字确认，不会自动触发。

## 系统快速解锁

- WebAuthn 使用平台通行密钥及 `userVerification: required`。系统可能采用 Face ID、Touch ID 或设备密码，应用不能保证只用某一种生物识别。系统凭据提供方也可能同步通行密钥；应用不读取生物信息。
- PRF 输出经 HKDF-SHA-256 派生 AES-GCM 包装密钥，包装既有随机数据密钥。PRF 输出、主密码和数据密钥明文均不写入浏览器存储。站点来源、RP ID、凭据、公钥、保险库和密码配置均绑定到包装上下文；每次验证挑战、UP/UV 标志和 ES256 签名，再实际解密。
- 授权时间另由数据密钥认证加密，永久或限时策略绑定到密钥包装上下文；仅修改明文期限或到期提示不能延长授权或切换为永久有效。永久绑定不按时间失效；限时绑定的计时依赖设备时钟，不能承诺抵御主动回拨时钟、复制旧数据库或已经被控制的设备。密码续期写入失败时保留密码访问，旧窗口不会被自动延长。
- 修改主密码、停用快速解锁、清空数据、覆盖恢复、删除本机保险库会撤销本地绑定。撤销失败会回滚对应数据库事务。应用不会删除系统密码管理器中的通行密钥，可由用户在系统设置中手动删除。
- 取消、手动锁定或离开设置页会中止进行中的系统调用；迟到结果不能重新打开空间或写入新的绑定。设置密码确认只在当前页面内存中保留，5 分钟后须重做；未验证启用的凭据不进入本地绑定。
- 不依赖应用后端。系统凭据提供方的离线能力需用实际 iPhone 验证。协议参考：[WebAuthn PRF](https://w3c.github.io/webauthn/#prf-extension)、[MDN 扩展说明](https://developer.mozilla.org/en-US/docs/Web/API/Web_Authentication_API/WebAuthn_extensions)。

## 加密备份与恢复

1. 设置 → 导出加密备份 → 输入并确认独立备份密码。
2. 生成完成后点击“保存备份文件”，使用系统分享存入“文件”App。也提供直接下载链接。仅生成尚未保存不算完成备份。
3. `.plog` 包含全部打卡、全部时段及小憩、完整 JPEG 和缩略图、模板、快捷标签、装备档案、小憩阈值、轮盘配置和判定历史；没有公开的照片路径、记录时间、备注或轮盘结果。
4. 新导出使用备份格式 v4（清单 v3）：密码派生独立密钥；清单和每张照片分别认证加密，绑定随机备份 id 与分段序号，最后有认证完成标志。按条目处理，不先把全部图片拼成 ZIP/base64。仍可导入原版 v2、扩展 v3 备份，旧备份没有轮盘数据时恢复默认轮盘与空历史；旧应用会拒绝 v4 备份，需要先更新再恢复，避免静默丢失轮盘历史。
5. 恢复：选择文件 → 输入备份密码 → 验证 → 查看条目数量 → “确认覆盖恢复”。验证密码、格式、引用唯一性、照片完整性、时段有效性和末尾完成标志。错误密码、截断、篡改、未知尾部和不支持版本都拒绝导入。
6. 全部验证通过才用当前本地密钥重新加密，准备好后以一次数据库事务覆盖。失败保留原有库，跨设备可使用不同的本地解锁密码。
7. 备份是完整覆盖恢复，不合并现有记录。恢复前建议先备份现有数据。大批数据需要等待，设备内存/存储不足时可失败；请保留原文件，在有足够资源的设备上恢复。

浏览器数据、PWA 数据及系统相册是不同存储。相册原图由系统保存与否取决于拍照入口；应用不会删除系统相册。浏览器清理、卸载、换网址、换浏览器、换设备都不能代替备份迁移。`navigator.storage.persist()` 只是申请，无法保证系统永远不清理。

## 离线与更新

Service Worker 只预缓存编译后的程序、离线 HEIC 转换代码、图标、启动图和清单。没有运行时照片缓存，也不向 Cache Storage 存入 object URL、照片或数据库备份。照片从 IndexedDB 解密到临时 blob URL。

更新使用提示模式，不自动重新载入正在编辑的页面。新资源可用后设置页提供更新入口，并提示先保存草稿；数据库不会因更新清空。**保持同一站点 origin 和应用入口**；换部署域名须通过备份迁移。强制清除 Safari 网站数据也会清掉数据库。
